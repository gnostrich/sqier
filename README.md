# sqier: Squier's theorem on finite derivation type, in Lean 4

[![consolidated build](https://github.com/gnostrich/sqier/actions/workflows/build.yml/badge.svg)](https://github.com/gnostrich/sqier/actions/workflows/build.yml)

A Lean 4 and Mathlib formalization of **Squier's theorem** for string rewriting
systems (Squier, Otto and Kobayashi, *A finiteness condition for rewriting
systems*, TCS 131, 1994): a finite convergent string rewriting system has
**finite derivation type**. Equivalently, finitely many 2-cells, one for each
critical pair, generate every homotopy between parallel derivations. Along the way the
development proves Newman's lemma, the critical pair lemma for string rewriting
and the finiteness of critical pairs. It also works through the
rewriting system of the symmetric group `S₃` as an example.

Registered in the Palomar registry as
[PALOMAR-2026-11-26-000002](https://palomar-registry.org/entry.html?id=PALOMAR-2026-11-26-000002&version=1)
(version 1, commit `37d3c23`).

## The picture

The rules of a rewriting system are the permitted moves on words. The
derivation graph has words as vertices and rewriting steps
`x l y → x r y` as edges. Two zig-zag paths with the same endpoints bound a
"hole" unless they can be shown equivalent. Here, equivalent means homotopic: related by
the smallest congruence that contains a chosen set `B` of 2-cells and the
independence squares (two steps on disjoint factors commute), identifies a step
followed by its inverse with the empty path, and is compatible with
concatenation, inversion and whiskering by contexts `x _ y`. Squier's theorem
says that for a terminating system, one resolution cell per critical pair fills
every hole.

## Exact claims

[`Challenge.lean`](Challenge.lean) imports only Mathlib, contains every
definition the statements use, and states the nine compared theorems with
`sorry`. It is the file to read to see exactly what is claimed.
[`Solution.lean`](Solution.lean) restates them and proves each by appeal to the
development in [`Squier/`](Squier). `comparator.json` selects all nine.

| Theorem (`SquierChallenge.`) | Statement |
|---|---|
| `newman` | Newman's lemma for an arbitrary relation: terminating and locally confluent implies confluent |
| `critical_pair_lemma` | a string rewriting system is locally confluent iff every critical branching is joinable |
| `confluent_iff_criticalPairs_joinable` | a terminating system is confluent iff every critical branching is joinable |
| `criticalBranchings_finite` | over a finite alphabet, a finite system has finitely many critical branchings |
| `squier_homotopy_basis` | **Squier.** For a terminating system, any set of cells that contains a resolution cell (in either orientation) for every critical branching is a homotopy basis |
| `squier_finiteDerivationType` | **Squier's theorem.** A finite convergent system over a finite alphabet has finite derivation type |
| `homotopy_nondegenerate` | the homotopy relation is not trivial: for the `S₃` system and no cells, the two rewrites `aaa → a` are not homotopic |
| `s3_convergent` | the system `aa → ε`, `bb → ε`, `bab → aba` of `S₃ = ⟨a, b ∣ a² = b² = 1, bab = aba⟩` is terminating and confluent |
| `s3_homotopy_basis` | its five explicit critical-pair cells `s3Basis` form a homotopy basis |

`squier_homotopy_basis` quantifies over the choice of resolutions: whatever
resolution is chosen for each critical pair, the resulting cells generate all
homotopies. `homotopy_nondegenerate` guards against a degenerate definition. If
the generators of the homotopy relation accidentally identified every pair of
parallel paths, finite derivation type would hold trivially; it does not.

### Definitions (in `Challenge.lean`, copied verbatim from `Squier/Defs.lean`)

- `Step R u v`: a rule `(l, r) ∈ R` applied in context `(pre, suf)`, with
  `u = pre ++ l ++ suf` and `v = pre ++ r ++ suf`.
- `Path R u v`: zig-zag paths, steps traversed forwards or backwards; with
  `comp`, `inv`, `Positive` and whiskering.
- `Branching`, `Step.Independent`, `Branching.IsCritical` and `criticalBranchings`:
  a critical branching is a pair of distinct, non-independent steps from a
  common source with minimal context. These are the overlaps and inclusions of
  two left-hand sides.
- `Homotopic B`: the inductive homotopy relation generated by `B`.
- `IsHomotopyBasis`, `FiniteDerivationType` and `Resolves`.

### Not claimed

- **Tietze invariance.** The statement that finite derivation type is a property of the monoid, independent of the
  finite presentation, is not formalized.
- **Squier's counterexample.** The monoid that is finitely presented, has decidable word problem and is not
  of finite derivation type is not formalized.
- **Homological finiteness.** Neither the condition FP₃ nor its homotopical counterpart is formalized.
- **The setting.** The 2-cells live on zig-zag paths modulo an explicitly generated congruence.
  Free (2,1)-categories and polygraphs are not used; the independence squares
  play the role of the exchange law.
- **Decidability of critical pairs.** It is shown only through finiteness and the worked example.
  No verified Knuth–Bendix procedure is included. The `S₅` example
  of the original brief is a planned follow-up.
- **Novelty.** These are classical results. We searched for a previous machine-checked proof
  of Squier's theorem and found none (see `formalization.yaml`). Priority is
  nevertheless unknown. Newman's lemma and the critical pair lemma have
  been formalized before, in other systems and in Lean (CSLib).

## Second entry: growth series are rational (`comparator-growth.json`)

[`ChallengeGrowth.lean`](ChallengeGrowth.lean) states seven theorems (namespace
`SquierGrowthChallenge`); metadata in [`growth/formalization.yaml`](growth/formalization.yaml).

| Theorem | Statement |
|---|---|
| `avoidCount_rational` | words avoiding a finite set of factors have a rational generating function (transfer matrix + Cayley–Hamilton) |
| `unique_normalForm` | for a terminating, confluent system, each element of Mathlib's `PresentedMonoid` has exactly one normal form |
| `growth_eq_avoidCount` | elements with a normal form of length `n` ↔ words of length `n` avoiding every left-hand side |
| `growth_rational` | hence the growth series (by normal-form length) is rational |
| `s3_growth`, `s3_card` | `S₃`: series `1 + 2z + 2z² + z³`, six elements |
| `comm2_growth` | `ba → ab`: `n + 1` elements of length `n`, series `1/(1-z)²` |

Proofs: `Squier/GrowthDefs.lean`, `Squier/Transfer.lean`, `Squier/Growth.lean`. The growth series
is by normal-form length; for length-reducing or shortlex complete systems this is the usual
growth series, but the general geodesic statement is not claimed.

## Third entry: point counts of graph hypersurfaces (`comparator-kontsevich.json`)

[`ChallengeKontsevich.lean`](ChallengeKontsevich.lean) states seven theorems (namespace
`KontsevichChallenge`); metadata in [`kontsevich/formalization.yaml`](kontsevich/formalization.yaml).
The graph polynomial `Ψ = ∑_T ∏_{e ∉ T} α_e` (spanning trees `T`) defines the graph hypersurface,
whose periods are Feynman amplitudes; Kontsevich asked whether its point count over `𝔽_q` is
always a polynomial in `q` (false in general, Belkale–Brosnan).

| Theorem | Statement |
|---|---|
| `kirchhoff_series`, `forest_series`, `kirchhoff_parallel`, `forest_parallel` | series/parallel rules for `Ψ` and the 2-forest polynomial `Φ` (`Φ/Ψ` = effective resistance) |
| `kontsevich_seriesParallel` | for every series–parallel graph, one integer polynomial gives the point count over every finite field |
| `banana_count` | exact count for `m` parallel edges |
| `k4_count` | `K₄` (the smallest non-series–parallel graph): `q²(q³ + q − 1)` points |

Proofs in `Kontsevich/`: the series–parallel count tracks four zero-pattern counts of `(Ψ, Φ)`;
homogeneity makes the ratio `Φ/Ψ` equidistributed, so the counts compose polynomially.

## Supporting development, not submitted: Fagin's zero-one law (`comparator-fagin.json`)

[`ChallengeFagin.lean`](ChallengeFagin.lean) states seven theorems (namespace `FaginChallenge`);
metadata in [`fagin/formalization.yaml`](fagin/formalization.yaml). For a first-order sentence
`φ` about graphs, the probability that `G(n, 1/2)` satisfies `φ` tends to `1` if the Rado graph
satisfies `φ` and to `0` otherwise; along the way: `2^(n choose 2)` graphs, extension properties
hold almost surely, the Rado graph has them, and countable graphs with them are isomorphic.
Proofs in `Fagin/`. **Prior work:** the Lean 4 project
[cslib-frontier](https://github.com/cslib-community/cslib-frontier) proved this earlier and more
generally (constant `p`, relational vocabularies); this is an independent Mathlib-only proof of
the graph case with `p = 1/2`.

## Building

```
curl -sSfL https://elan.lean-lang.org/elan-init.sh | sh -s -- -y --default-toolchain none
lake exe cache get
lake build
```

Toolchain `leanprover/lean4:v4.35.0`, Mathlib `v4.35.0`, and Lean's module
system throughout. CI runs `lake build` with a sorry census, plus `lake comparator`
with Lean's kernel and the toolchain's bundled NanoDa and con-ron kernels.
